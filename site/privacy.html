Privacy

What leaves your computer

Suura is a local music player, so the honest answer is: very little, and only when it has to. There is no account, no analytics and no telemetry. This page lists every request the app can make so you can check it against what you see.

Last updated 8 November 2026. This statement describes Suura 0.1.0 and later.

The short version

  • Nothing is collected by the developer: no identifier, no usage count, no crash upload.
  • One request happens without you asking: the daily update check. It can be turned off, and the feed address can be cleared, in Settings → About.
  • Everything else — YouTube, lyrics, tags, covers, the engine download — contacts a server only when you press the button that needs it.
  • Crash reports are written to this computer and are off by default. They are never uploaded.
  • Your music files are never moved, renamed or uploaded. Their tags change only when you edit them.

The update check

About twenty seconds after launch, and at most once a day, Suura asks its update feed whether a newer version exists. Pressing Check now in Settings → About asks the same question. When you choose Download update, the installer comes from that same feed.

The default feed is a Cloudflare R2 bucket; the address is shown in Settings → About and can be cleared, which stops the check completely. The request carries what any web request carries — your IP address and a user agent naming the app and its version — and nothing about your library, your queue or what you have played. Cloudflare serves the feed and keeps its own request logs under Cloudflare's privacy policy.

Requests you start yourself

These only happen after an action, and each one needs the title, artist, album or duration you are asking about. None of them receives your file paths or your listening history.

  • YouTube — searching, pasting a link and streaming go to YouTube through yt-dlp and YouTube's own API. YouTube sees your IP address as it would in a browser. If you enable the optional browser-cookie fallback, the cookies you chose are used for those requests, which is what lets a signed-in session work.
  • Lyrics — LRCLIB and Genius are asked for the track title, artist, album and duration when you press Find lyrics or run a batch.
  • Tags and covers — the iTunes Search API, MusicBrainz and the Cover Art Archive are asked when you use Find tags or choose a cover. AcoustID fingerprinting uses AcoustID with a key you enter yourself, and only after you ask for a fingerprint.
  • The engine — yt-dlp, ffmpeg and fpcalc are downloaded from their projects' GitHub releases the first time a feature needs them, and updated only on request.
  • The PO Token provider — if you enable one, Suura talks to the local address you set (by default http://127.0.0.1:4416). Suura opens no listening socket; the provider is a separate program you install and run, and it is the one that talks to Google.

Cookies and sign-in

Suura has no account of its own. The optional cookie fallback exists only for YouTube requests that need a signed-in session. It is off by default, and when you turn it on you pick either a browser profile on this computer or a Netscape cookies.txt file. Suura stores the location you picked in its settings, reads the file for yt-dlp, and sends it nowhere else. Reset preferences leaves that location alone, because it is a place on disk rather than a taste.

What stays on this computer

Suura keeps its own data in %APPDATA%\Suura: the library database, automatic backups, the stream cache, downloaded engine binaries, logs, and crash reports if you turned them on. Your music stays where you keep it, and anything Suura saves goes where you choose (by default Music\Suura).

Uninstalling removes the program. The uninstaller asks before deleting the data folder, and the safe answer — keep it for a later reinstall — is the default. You can also delete the folder yourself at any time.

Turning on Start Suura when I sign in adds one entry to your Windows sign-in items and changes nothing else on the computer. The uninstaller removes that entry even if you keep your data.

Crash reports and logs

Crash reports are off by default. When you turn them on in Settings → Misc, Suura writes a small text report beside its other data if the app or its window process crashes; Settings can list, export and clear them. Nothing is uploaded. If you report a bug, you choose whether to attach a report, and you can read it first.

The app also keeps a local log for troubleshooting. It stays on this computer unless you use Save diagnostics, which writes a bundle to a file you pick. Both can contain local file paths, so review them before sharing.

This website

This page is static and loads nothing from third parties: no analytics, no advertising, no remote fonts, no cookies. Cloudflare Pages serves it and, like any web host, sees the requests it serves; that is covered by Cloudflare's policy rather than by anything this page runs.

Changes

If a future version makes a new kind of request, this page changes with it and the date above moves. The source is public: the network calls live in the repository, and the licences of everything Suura runs are listed in THIRD-PARTY.md. Questions go to the issue tracker.
